# Стандарт кода: Swift

## Назначение

Краткий практический стандарт Swift для этого репозитория (macOS-приложение
NotchClaude). Написан и для человека, и для агентов, которые пишут или ревьюят
здесь код. Проект маленький и должен таким остаться, поэтому правил ровно
столько, сколько реально применяется.

## Таблица решений (11 правил)

| #   | Правило                                                                  | Уровень | Обоснование                                                                                 |
| --- | ------------------------------------------------------------------------ | ------: | ------------------------------------------------------------------------------------------- |
| 1   | Swift 6 со strict concurrency, без понижения языкового режима            |    FAIL | Гонки ловит компилятор, а не отладчик. Отключение режима прячет реальные проблемы.          |
| 2   | Весь код, трогающий UI, помечен `@MainActor`                             |    FAIL | AppKit/SwiftUI не потокобезопасны; без аннотации падения плавающие и невоспроизводимые.     |
| 3   | Никаких force-unwrap (`!`) и `try!` кроме доказуемо безопасных            |    FAIL | Крашит приложение у пользователя. Исключение — с комментарием, почему nil невозможен.       |

## Пояснения к правилам

### 1. Concurrency

- `swift-tools-version:6.0` в `Package.swift`, никаких
  `.swiftLanguageMode(.v5)` и `-strict-concurrency=minimal`.
- Общее изменяемое состояние либо изолировано актором/`@MainActor`, либо
  отсутствует. Предпочтительный вариант — отсутствует: `UsageReader` — `enum`
  без свойств, чистая функция от каталога и времени.
- Фоновая работа — `Task.detached`, возврат результата через
  `await MainActor.run { ... }`.
- `nonisolated(unsafe)` допустим только с комментарием, доказывающим
  безопасность (пример — переиспользуемый `ISO8601DateFormatter` в
  `Usage.swift`, читаемый из одной задачи).

### 2. UI

- `@MainActor` на классах, а не на отдельных методах: `Model`,
  `NotchController`.
- SwiftUI-`View` — структуры без внешних побочных эффектов; вся работа с файлами
  и таймерами живёт в контроллере/модели.
- Форматирование чисел и текста — свободные функции (`fmt`), не методы вью.

### 3. Опционалы и ошибки

- `try?` + `guard ... else { continue }` для файловых операций: нечитаемый файл
  не должен ронять весь проход.
- `precondition` уместен в самопроверках и для нарушений инвариантов кода;
  не для внешних данных.
- Никаких пустых `catch {}` без комментария.

### 4. Внешние данные

- Каждое поле JSON: явный `as?` с fallback (`?? 0`, `?? ""`).
- Изменение схемы логов должно проявляться как нулевые числа, а не как краш.
- Новое читаемое поле — новая проверка в `selfTest()`.

### 5. Зависимости

- Разрешено: Foundation, AppKit, SwiftUI, Combine и прочие системные фреймворки.
- Всё остальное — только если задача не решается разумным объёмом своего кода;
  обоснование пишется в `docs/architecture.md`.
- Тестовых фреймворков в проекте нет: проверка — `--selftest`.

### 6. Стиль

- Именование: `UpperCamelCase` для типов, `lowerCamelCase` для всего остального.
- Тип в объявлении не дублируется, если он очевиден из значения
  (`var input = 0`, не `var input: Int = 0`).
- Doc-комментарии `///` на типах и публичных функциях; построчные комментарии —
  только там, где непонятно «почему», а не «что».

## Проверки

```bash
swift build -c release              # сборка без предупреждений
swift run NotchClaude --selftest    # самопроверка парсера
swift run NotchClaude --dump        # снимок по реальным логам
```

Линтера в проекте нет: SwiftLint/swift-format для ~450 строк — лишняя
зависимость и лишний CI-шаг. Добавить, когда правила начнут нарушаться
регулярно.

## Чеклист ревьюера (8 пунктов)

1. `swift build -c release` проходит без предупреждений.
2. `swift run NotchClaude --selftest` проходит.
3. Нет новых force-unwrap без комментария-обоснования.
4. Новый код, трогающий UI, под `@MainActor`.
5. Новые поля внешних данных читаются со значением по умолчанию.
6. Новых сторонних зависимостей нет (или обоснование в `architecture.md`).
7. Новая нетривиальная логика покрыта проверкой в `selfTest()`.
8. Осознанные упрощения помечены `ponytail:` с указанием потолка и апгрейда.
