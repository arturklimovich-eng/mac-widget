# NotchClaude — Архитектура

**Дата:** 2026-08-13
**PRD:** [PRD.md](PRD.md)

## Краткое описание

Одно исполняемое приложение (~450 строк Swift 6), собираемое SPM без
Xcode-проекта. Два независимых слоя: чистая функция чтения логов Claude Code и
AppKit-панель поверх чёлки, которая эту функцию вызывает по таймеру, пока
раскрыта. Сети, БД, состояния на диске и сторонних зависимостей нет.

## Стек

| Слой | Выбор |
| --- | --- |
| Язык | Swift 6, strict concurrency |
| UI | SwiftUI (содержимое) + AppKit (`NSPanel`, `NSHostingView`, `NSTrackingArea`) |
| Реактивность | Combine (`ObservableObject`, `@Published`) |
| Сборка | SwiftPM, `platforms: [.macOS(.v14)]`, executableTarget |
| Упаковка | `bundle.sh` → `build/NotchClaude.app` (Info.plist + ad-hoc `codesign`) |
| Зависимости | нет |

## Компоненты

| Компонент | Файл | Ответственность |

## Поток данных

```
~/.claude/projects/<project>/<session>.jsonl
        │  (файлы фильтруются по mtime ≥ min(начало суток, сейчас − 5 ч))
        ▼
UsageReader.files() ──► построчно ──► UsageReader.entry(from:)
                                          │  "type":"assistant" + message.usage
                                          ▼
                              дедуп по message.id|requestId
                                          ▼
                          агрегация: today / block(5 ч) / session
                                          ▼
                                      Snapshot
        ▲                                 │
        │  Task.detached каждые 3 с       ▼  await MainActor.run
   NotchController.ticker ──────────► Model.snap  ──►  StatsView
                                          ▲
                          Model.expanded ─┘  (mouseEntered/mouseExited)
```

Направление одностороннее: наведение меняет `expanded`, `expanded` включает
таймер, таймер обновляет `snap`, `snap` перерисовывает `StatsView`. Обратной
связи от UI к чтению логов нет, состояние никуда не сохраняется.

## Решения и обоснования

### SPM-пакет вместо Xcode-проекта

`Package.swift` — 10 строк текста в git; `.xcodeproj` — бинарно-подобный XML,
который конфликтует при мерже и не читается в diff. Для однотаргетного
приложения без ресурсов, storyboard'ов и entitlements Xcode-проект не даёт
ничего. Бандл `.app` собирается 20 строками `bundle.sh` — Info.plist здесь
короче, чем один tab в настройках таргета. Цена решения: нет превью SwiftUI и
отладчика из коробки; для одного экрана это приемлемо.

### `NSTrackingArea` с `.activeAlways` вместо SwiftUI `.onHover`

Панель `.nonactivatingPanel` — она специально не забирает фокус, иначе наведение
на чёлку выбивало бы курсор из активного редактора. Но SwiftUI `.onHover` в
неактивном приложении события не получает: hover-трекинг SwiftUI работает через
tracking area с `.activeInKeyWindow`. Поэтому наведение отслеживается вручную —
подклассом `NSHostingView`, который в `updateTrackingAreas()` пересоздаёт
`NSTrackingArea` с `[.mouseEnteredAndExited, .activeAlways, .inVisibleRect]`.
`.activeAlways` — единственный вариант, работающий при неактивном приложении;
`.inVisibleRect` избавляет от пересчёта прямоугольника при смене размера панели.

### Чтение jsonl вместо API или обёртки над CLI

Claude Code уже пишет всё нужное на диск в `~/.claude/projects/**/*.jsonl` —
по строке на событие, с полем `message.usage`. Это даёт точные цифры бесплатно:
не нужен API-ключ, не нужно оборачивать процесс, не нужно ничего парсить из
терминального вывода. Формат читается 50 строками кода. Риск — недокументированный
формат (см. ниже), плата за него ниже, чем за любую альтернативу.

### Полный перечитыв файлов вместо инкрементального чтения

Файлы отбираются по mtime, поэтому за один проход читаются только логи текущих
суток и текущего окна — на практике единицы мегабайт, десятки миллисекунд в
фоновой задаче раз в 3 секунды. Хранение offset'ов потребовало бы состояния на
диске и обработки усечения/перезаписи файлов. Помечено в коде как
`// ponytail:` с указанием апгрейда — читать хвост от запомненного offset, если
станет медленно.

### Никакой сети

Приложение показывает локальные данные и не имеет причин куда-то ходить. Прямое
следствие: не нужны entitlements на сеть, нет вопроса «что уходит наружу»,
нечего ломаться в офлайне и нечему протекать. Отсутствие сетевого кода — не
недоделка, а требование (NFR1).

### `Timer` только в раскрытом состоянии

Свёрнутая панель — самое частое состояние приложения (почти всегда). Таймер
создаётся в `setExpanded(true)` и инвалидируется при сворачивании, поэтому в
простое приложение не делает ничего: ни файловых операций, ни пробуждений.
Альтернатива — `FSEvents`/`DispatchSource` на каталог логов — дала бы обновление
в реальном времени, но данные никто не видит, пока панель свёрнута.

### Чтение логов в `Task.detached`, UI на `@MainActor`

Проход по логам — синхронный файловый I/O, на главном потоке он бы подмораживал
анимацию. `Model.refresh()` уходит в `Task.detached` и возвращает результат
через `await MainActor.run`. `Model` и `NotchController` помечены `@MainActor`,
`UsageReader` не имеет изменяемого состояния — этого достаточно, чтобы strict
concurrency Swift 6 не требовал ни блокировок, ни акторов. Единственное
исключение — переиспользуемый `ISO8601DateFormatter`, помеченный
`nonisolated(unsafe)` с комментарием, почему это безопасно (читается только из
одной фоновой задачи).

## Риски и ограничения

| Риск / ограничение | Влияние | Что делаем |
| --- | --- | --- |
| Формат логов Claude Code недокументирован и может измениться | Цифры замолчат или обнулятся | Парсинг устойчив к отсутствующим полям (значения по умолчанию), `--selftest` фиксирует ожидаемый формат, `--dump` даёт быструю проверку на реальных данных |
| Расход в токенах ≠ фактический лимит | Числа информативны, но не «X% лимита» | Осознанно: точные правила лимитов Claude непубличны, показываем сырой расход |
| Нет стоимости в деньгах | Не видно расхода в валюте | Вне MVP: нужна и требует поддержки таблица цен моделей |
| Файлы перечитываются целиком | Рост CPU при очень больших логах | mtime-фильтр ограничивает объём; апгрейд помечен `ponytail:` в коде |
| Только один экран с чёлкой | На втором MacBook-экране панели нет | Вне MVP, `NSScreen.screens.first { safeAreaInsets.top > 0 }` |
| Ad-hoc подпись | Gatekeeper поругается при переносе на другую машину | Осознанно: приложение собирается локально автором |
| `NSScreen.main!` в фолбэке | Теоретический краш без экранов | Приложение с GUI без экранов не запускается; допустимый force-unwrap |
| Панель поверх меню-бара | Может перекрывать элементы в чёлке | Свёрнутая панель прозрачна и ровно по границам чёлки |

## Как тестируется

- **`swift run NotchClaude --selftest`** — основная проверка. Создаёт временный
  каталог с синтетическим `a.jsonl`, где есть дубль записи, запись вне
  5-часового окного, запись другой сессии и не-`assistant` строка, затем
  проверяет `precondition`-утверждениями: число ответов в окне, суммы по каждой
  составляющей, выбор самой свежей сессии, имя проекта из `cwd`, модель, полный
  total. Без фреймворков и фикстур: одна функция, один запуск, ненулевой код
  возврата при поломке.
- **`swift run NotchClaude --dump`** — печатает снимок по реальным логам:
  проверка, что парсер согласуется с настоящим форматом, а не только с
  синтетическим.
- **`swift run NotchClaude --show`** — панель раскрыта сразу, без наведения:
  проверка, что она вообще рисуется и в нужном месте.
- **CI** (`.github/workflows/build.yml`, macos-15) — `swift build -c release`,
  затем `.build/release/NotchClaude --selftest`.

UI-тестов нет: единственный интерактивный элемент — наведение, и его проверка
автоматом стоила бы больше, чем весь остальной проект.
