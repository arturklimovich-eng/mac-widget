# NotchClaude — Product Requirements Document

**Дата:** 2026-08-13
**Уровень проекта:** одноэкранный виджет для личного использования
**Бриф:** [product-brief-notch-claude-2026-08-13.md](product-brief-notch-claude-2026-08-13.md)
**Архитектура:** [architecture.md](architecture.md)

## Краткое описание

macOS-агент, показывающий расход токенов Claude Code при наведении курсора на
чёлку MacBook. Данные берутся из локальных логов Claude Code, сеть не
используется. Один экран, один жест, никаких настроек.

## Сценарии использования

1. **Проверка остатка лимита.** Идёт долгая сессия, автор хочет понять, стоит ли
   запускать ещё одну большую задачу. Ведёт мышь к чёлке, читает расход за
   5-часовое окно, убирает мышь. Активное окно не меняется.
2. **«Он ещё думает или уже ждёт меня?»** Терминал с Claude Code скрыт за
   браузером. Наведение на чёлку показывает зелёный/серый индикатор и «активность
   N мин назад».
3. **Итог за день.** Вечером — взгляд на строку «Сегодня», чтобы понять, сколько
   ушло за день целиком.
4. **Проверка данных из терминала.** `swift run NotchClaude --dump` печатает тот
   же снимок текстом — удобно, когда нужно сравнить с ощущениями или отладить
   парсер.

## Функциональные требования

### FR1: Чтение логов Claude Code

Приложение обходит `~/.claude/projects/**/*.jsonl`, отбирая файлы по mtime (не
раньше начала суток и не раньше начала 5-часового окна). Каждая строка —
отдельный JSON-объект; берутся объекты с `"type":"assistant"`, из них
`message.usage` (`input_tokens`, `output_tokens`, `cache_creation_input_tokens`,
`cache_read_input_tokens`), `timestamp`, `sessionId`, `cwd`, `message.model`.

### FR2: Дедупликация записей

Один и тот же ответ модели может встречаться в логах несколько раз. Записи
дедуплицируются по ключу `message.id` + `requestId`; повторы в суммы не
попадают.

### FR3: Агрегация по трём периодам

- **Окно 5 часов** — скользящее окно от «сейчас минус 5 часов» (окно лимитов
  Claude), плюс счётчик ответов модели в этом окне.
- **Сегодня** — с начала календарных суток в локальной таймзоне.
- **Сессия** — сумма по `sessionId` самой свежей записи.

Для каждого периода показываются четыре составляющие (in / out / cache write /
cache read) и общая сумма.

### FR4: Индикатор активности

Claude считается активным, если самая свежая запись в логах моложе 60 секунд.
Отображается цветной точкой (зелёная / серая), подписью «Claude работает» /
«Claude простаивает» и строкой «активность N с/мин назад».

### FR5: Контекст сессии

Показываются текущая модель (`message.model`, префикс `claude-` отбрасывается) и
имя проекта — последний компонент пути `cwd`.

### FR6: Геометрия чёлки

Целевой экран — первый с `safeAreaInsets.top > 0`. Ширина чёлки считается как
`frame.width − auxiliaryTopLeftArea.width − auxiliaryTopRightArea.width` (на
MacBook Air 13" M4 — 179×32 pt). Если чёлки нет (внешний монитор) —
используется полоска 200 pt по центру верхнего края.

### FR7: Раскрытие по наведению

Прозрачная `NSPanel` уровня выше меню-бара, свёрнутая ровно по границам чёлки.
Наведение курсора раскрывает панель вниз (анимация 0.15 с, easeOut), уход
курсора — сворачивает. Панель `.nonactivatingPanel`: фокус активного приложения
не отбирается.

### FR8: Обновление данных

Снимок пересчитывается при раскрытии и далее каждые 3 секунды, пока панель
раскрыта. В свёрнутом состоянии таймер остановлен и логи не читаются.

### FR9: Выход

Кнопка «Выход» в раскрытой панели завершает приложение. Иконки в Dock нет
(`LSUIElement`), поэтому это единственный способ выйти из GUI.

### FR10: Режимы командной строки

- `--selftest` — самопроверка парсера на синтетическом логе (`precondition`),
  печатает `selftest ok`, код возврата 0.
- `--dump` — печатает текущий снимок по реальным логам и выходит.
- `--show` — запуск с уже раскрытой панелью (проверка отрисовки без наведения).

## Нефункциональные требования

### NFR1: Приватность и локальность

Ноль сетевых запросов: приложение не содержит сетевого кода вообще. Читаются
только файлы внутри `~/.claude/projects`. Не требуется ни одного разрешения
macOS (ни Accessibility, ни Screen Recording, ни Full Disk Access) — логи лежат
в домашнем каталоге пользователя. Никакой телеметрии.

### NFR2: Задержка раскрытия

Панель начинает раскрываться в том же событии `mouseEntered`; анимация — 0.15 с.
Первый снимок может прийти чуть позже (чтение логов уходит в фоновую задачу), в
этот момент показываются предыдущие значения.

### NFR3: Потребление CPU в простое

В свёрнутом состоянии активных таймеров нет, логи не читаются — расход CPU
неотличим от нуля. Пока панель раскрыта — один полный проход по логам раз в
3 секунды в фоновой задаче.

### NFR4: Платформа

macOS 14+ (Sonoma), Swift 6 toolchain, SwiftUI + AppKit. Сборка через SPM;
Xcode-проект не требуется. Архитектуры: сборка нативная под машину разработчика
(universal binary не собирается).

### NFR5: Отсутствие зависимостей

Только системные фреймворки (Foundation, AppKit, SwiftUI, Combine). Сторонние
пакеты не подключаются — добавление любого требует обоснования (см.
[standards/swift.md](standards/swift.md)).

### NFR6: Устойчивость парсинга

Логи — внешние данные и их формат может измениться. Битая строка, отсутствующее
поле или нечитаемый файл не приводят к падению: строка пропускается,
числовые поля получают значение по умолчанию 0, строковые — пустую строку.

### NFR7: Проверяемость

Вся нетривиальная логика (парсинг, дедуп, границы окон) покрыта `--selftest`,
который запускается в CI на каждый push.

## Отложено (вне MVP)

- Оценка расхода в деньгах — требует поддерживаемой таблицы цен по моделям.
- Автозапуск при входе в систему.
- Экран настроек любого вида.
- Графики и история расхода за прошлые периоды.
- Инкрементальное чтение логов (сейчас файлы перечитываются целиком при каждом
  обновлении).
- Одновременная поддержка нескольких экранов с чёлкой.
- Предупреждение при приближении к лимиту.
